# Multilanguage (i18n)

Languages: `es` (default), `en`, `pt`. Default is Spanish and stays Spanish until the
user explicitly picks another language — do NOT re-introduce navigator/browser-language
auto-detection (the confirmed product requirement is "default Spanish").
**Why:** navigator detection silently overrode the Spanish default and showed English to
English-locale browsers, contradicting the spec.

## Frontend (`artifacts/sember-connect`)
- react-i18next, single `translation` namespace. `src/i18n/index.ts` merges per-section
  JSON files (`locales/{es,en,pt}/{common,home,opportunities,organizations,auth,profile,panel,admin}.json`)
  by spread. Each section file has exactly ONE top-level key = its section name; add new
  keys under that key and keep the three languages structurally identical.
- Persisted in localStorage key `sember-lang`; `document.documentElement.lang` updated on change.
- Domain enum labels are localized via `useDomainLabels()` in `src/lib/constants.ts`
  (returns localized `{value,label}[]` arrays + `*Label(value)` helpers). The old
  `OPPORTUNITY_TYPES`/`ORGANIZATION_TYPES`/`MODALITIES` exports were removed — never
  reference them; stored enum VALUES stay unchanged, only display text is translated.
- Locale is sent to the API: `main.tsx` calls `setLocaleGetter(() => getCurrentLanguage())`;
  `lib/api-client-react/src/custom-fetch.ts` injects an `accept-language` header on every request.
- Zod form validation messages are localized by defining the schema INSIDE the component
  (or a `createXSchema(t)` factory) so `t()` is in scope.

## Backend (`artifacts/api-server`)
- `src/lib/i18n.ts` = flat-key catalog + `t(locale, key, params?)` ({{var}} interpolation,
  falls back to default locale then the raw key) + `detectLocale(acceptLanguage)`.
- `src/middlewares/locale.ts` sets `req.locale` (default `es`) and augments the Express
  Request type; mounted in `app.ts` before routes.
- Route handlers return `t(req.locale, "...")` for all user-facing messages, including
  generic Zod-failure responses (`common.invalidData` for body, `common.invalidParams`
  for query/params) — do NOT return raw `parsed.error.message` (leaks verbose English).
- **Error `code` values must never change** (frontend keys off them, e.g.
  `email_no_verificado`, `pendiente_aprobacion`) — only the human-readable message text is localized.
- OTP verification email: `sendOtpEmail(..., locale)` localizes subject + body; register
  and resend-otp handlers pass `req.locale`.
